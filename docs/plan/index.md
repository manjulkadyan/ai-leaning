# Study Plan

The plan turns the [Roadmap](../roadmap/index.md) into something you do every day. It assumes **1.5–2 hours on weekdays** and **3 hours on one weekend day**, for 52 weeks. If you have less time, stretch it; never skip the review days.

## The three rhythms

| Rhythm | What happens | Time |
|---|---|---|
| **Daily** | One lesson: read, run the code, do the exercises, tick the checklist | 90–120 min |
| **Weekly** | Day 6 is a review + mini-project; Day 7 is rest | 3 h + rest |
| **Monthly** | A milestone project that proves the month's skills, plus a written retrospective | Last weekend |

## A daily session

1. **Warm-up recall (10 min).** Without looking, write down three things from yesterday's lesson. Then check. This is *active recall*, and it's the single most effective study habit there is.
2. **Read the lesson (30–40 min).** Type the code yourself rather than copy-pasting.
3. **Exercises (30–45 min).** Do them before looking at solutions.
4. **Log it (5 min).** Add an entry to your learning journal (see below) and tick the lesson's checklist.

!!! tip "Learning journal"
    Keep a `journal/` folder in a private repo with one Markdown file per week. For each day write: what you learned in two sentences, what confused you, and one question to look up. Reviewing it on Day 6 is how confusion gets resolved instead of buried.

## Weekly review (Day 6)

- Re-do the hardest exercise of the week from a blank file.
- Build the week's mini-project (listed in each week's plan).
- Answer the week's self-check questions aloud, as if explaining to a junior engineer.
- Write the weekly retro: what went well, what to repeat, what to change.

## Monthly milestone

Each month ends with a milestone project from the roadmap. A month counts as complete when:

- [ ] The milestone project runs from a clean checkout with a README.
- [ ] You can explain every line of it.
- [ ] You wrote a short retrospective and adjusted next month's plan if needed.
